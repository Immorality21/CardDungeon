# Meta-Progression / Hub (`Assets.Scripts.Progression`)

The persistent between-run economy, on top of hero XP.

- **MetaProgressManager** (singleton): owns two currencies and permanent magic upgrades, persisted to `Meta.json` **immediately on every change** (not deferred), so awards survive party death when dungeon/run saves are wiped.
  - **Gold** — flow currency, spent at the merchant.
  - **Essence** — investment currency, spent upgrading magic.
  - **Magic upgrades** are tracked **per magic key** (per magic type). Each level adds a flat `PowerPerUpgradeLevel` to that magic's Damage/Heal effect power whenever a hero casts it (Buff/Debuff power unaffected), **and unlocks any of its effects gated behind that level** (`SpellEffect.UnlockLevel`). Cost scales per level; capped at `MaxMagicUpgradeLevel`.
  - **Combo upgrades** work identically, keyed by `MagicComboSO.Key`, reusing the same curves (`GetComboUpgradeLevel/Cost`, `CanUpgradeCombo`, `TryUpgradeCombo`, `GetComboPowerBonus`). A combo is upgradeable only once **discovered**.
  - **Discovery** (permanent, survives death): `MarkMagicDiscovered`/`IsMagicDiscovered` and `MarkComboDiscovered`/`IsComboDiscovered`, stored as `DiscoveredMagicKeys`/`DiscoveredComboKeys` in `Meta.json`. Drives the Forge's collection grid (`?` for undiscovered). **A magic is discovered when some hero first learns it on their sphere grid** (`SphereGridUI.OnActivate`); before 2026-09-04 the trigger was drawing it from an enemy. What the Inspect and Bestiary pages mask is a *different* record now — `BestiaryEntry.ObservedSpellKeys`, per enemy, written when the player actually watches that monster cast (see the Enemies guide).
  - **Enemy knowledge / the bestiary** (permanent, survives death): `MarkEnemySeen`, `MarkResistanceObserved`, `MarkAttackTypeObserved`, `MarkEnemyKilled`, `MarkLootObserved`, read back through `GetBestiary`/`GetBestiaryEntry`/`IsEnemySeen`. Stored as `Bestiary` (a `List<BestiaryEntry>`) in `Meta.json`, keyed by `EnemySO.SaveKey`. Drives the in-combat **Inspect** page and the hub **Bestiary** — see the Enemies guide for the presentation rules.
    - **The rules are pure (`BestiaryOps`) and every mutator returns whether it changed anything**, and the manager persists *only* then. That is not tidiness: these are called from the damage path, on **every hit**, so a mutator that always saved would rewrite `Meta.json` several times a turn.
    - **Written where the player sees the thing**, all in `CombatManager`: seen at combat start; the damage type on every landed hit (`ExecuteAttack` and, for casts, `RecordCastDamageObserved` over the magic's live `Damage` effects); the attack element when an enemy swings; kills and loot in `HandleEnemyDeath`, loot only when it actually dropped.
    - **A hit records its element even when the outcome is neutral.** The original plan said to record only a non-`Normal` classification; that would leave every neutral element unreadable forever, since "Lightning does nothing special to this" is a real finding. `BestiaryTests` pins it.
    - **Only the observed *types* are stored, never the percentages** — those are read back off the live `EnemySO`, so retuning an enemy cannot leave a save quoting stale numbers.
  - **Magic slot growth moved to the sphere grid** (per-hero `MagicSlot` nodes bought with XP — see the Heroes guide). The old Essence-bought global upgrade (`TryUpgradeSlots`/`BonusSlots`) is retired: `MetaProgressSaveData.BonusSlots` survives only as a legacy field, and `MetaProgressManager` refunds the Essence in full (historical prices, 40 + 40·i) on the first load after the change, then zeroes it.
  - **Party slots**: `BonusPartySlots` raise how many heroes can be **fielded at once** — `GetPartyCap()` = `PartySlots.CapForBonus(bonus)`, base 2 up to a ceiling of 4, bought with **Gold** (`TryBuyPartySlot`, rising price per slot in `PartySlots.CostForNext`). Gold rather than Essence because it buys roster width, the same axis the tavern sells into; Essence stays reserved for magic. Sold on the **Party** screen, not the Merchant, so the cost of a wider party sits beside the XP share it dilutes.
  - **Pure helpers** `MagicPowerBonusForLevel` / `MagicUpgradeCostForNextLevel` hold the economy math (no state/disk) so it's unit-testable (`MagicUpgradeTests`). Tuning constants live at the top of the manager.
- **Awards** (both call the manager, which auto-creates if absent):
  - `DungeonManager.OnDungeonCleared` → `AwardLevelClear()` (flat Gold + Essence per level cleared, **plus** the level's accumulated kill-gold — see pending gold below).
  - `DungeonManager.HandlePartyDeath` → `AwardRunProgressOnDeath(levelIndex)` (consolation Gold scaled by how far the run reached), awarded **before** saves are wiped; also `DiscardPendingGold()`.
- **Pending kill-gold** (`_pendingRunGold`, in-memory, not persisted): enemies grant `GoldReward` per kill (`AddPendingGold`), **shown in the victory summary** but only banked into persistent Gold on level-clear (`AwardLevelClear` commits + resets it). A wipe forfeits it (`DiscardPendingGold`) — so gold, like XP/items, is only kept by clearing the level. (XP is awarded immediately per kill and committed on dungeon-clear like before; it is now actually sourced — enemies grant `EnemySO.XpReward`.)
- **Combat integration:** `CombatManager.ExecuteCastAction` reads `GetMagicPowerBonus(magicKey)` and passes it as `EffectResolver.Execute(..., powerBonus)`. The resolver folds the bonus into a *copy* of each Damage/Heal effect (never mutates the `MagicSO`).
- **Hub UI (spend sinks):**
  - **MerchantUI** (`MainMenu/MerchantUI.cs`) — Gold sink. Three offers: (1) enlarge the potion belt (raises `PartyResourceManager` healing-potion max, escalating cost); (2) **buy gear** from a rotating stock; (3) **sell** spare gear back at a loss.
    - **Stock** is persisted in `MetaProgressSaveData.ShopStock` (item keys) so it's stable across sessions and can't be free-rerolled by reopening. Generated when empty (weighted by rarity — rarer is less likely, equipment only, no dupes); a **Restock** button rerolls it for Gold. Buying removes that key from the stock. Accessors: `MetaProgressManager.GetShopStock/SetShopStock/RemoveFromShopStock`.
    - **Pricing** is pure/testable: `Items/ShopPricing.cs` (`BuyPrice`/`SellPrice`, scales with rarity + item level; sell = buy × `SellFraction` 0.4). Covered by `ShopPricingTests`.
    - **Selling** uses `InventoryManager.RemoveBagEquipment(key)` — removes one **un-equipped** copy only, so selling a duplicate never strips a hero's equipped gear (buy = `AddItem`, sell pays via `AddGold`). Both persist immediately in the hub.
  - **PartySelectUI** (`MainMenu/PartySelectUI.cs`) — Gold sink for **party width** plus the fielded-lineup choice itself. See the MainMenu and Heroes guides.
  - **MagicForgeUI** (`Cards/UI/MagicForgeUI.cs`, the "Forge") — Essence sink + collection screen. Two tabs (All Magic / Combos) over a **grid** of every catalog entry: real icon for discovered, `?` for undiscovered. Click a cell to inspect (name, description, effects with their unlock levels) and upgrade. Combos upgrade only once discovered. (Slot growth lives on the sphere grid now — per-hero `MagicSlot` nodes bought with XP, not an Essence purchase.)
  - Both panels are built and wired by the editor script — see the MainMenu guide.
