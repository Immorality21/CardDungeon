# Outside playtest, 2026-10-30: the owner's verdicts

An outside playtester's notes (the itch.io build), gone through with the owner on 2026-10-30. This
file holds the verdicts until they are moved into the plan files they belong to (`NEXT_STEPS.md`,
`COMBAT_DEPTH.md`, `POLISH_CONTENT.md`, `HUB.md`, `DUNGEON_ROOMS.md`), then it is deleted.

**Order of work (owner):** 1) the text system (below), 2) the accepted fixes, 3) move the roadmap
items into the plan files.

## 1. The text system (first)

- **Every player-facing text goes through one localization table.** Code and ScriptableObjects hold
  **keys** (`hero.warrior.name`, `hero.warrior.description`, `ui.hub.forge.name`); the table turns a
  key into English (the default) and later into other languages.
- **Stored in Unity** (a ScriptableObject table), edited in **one editor window**. No translators
  planned: the owner will translate.
- Scope: UI labels and buttons, content names and descriptions (heroes, abilities, items, enemies,
  sets, room events, ...), tutorial and event lines, and composed lines with numbers (as templates
  with named placeholders).
- **Texts are moved as-is.** The owner rewords them in the window.
- **Asset keys are derived from the asset's `Key`** (`hero.warrior.name`, `magic.ice-shard.description`);
  the Name/Description fields leave the assets, and the inspector shows the English inline (edits
  go to the table).
- **UXML: the text holds the key**, `text="#ui.hub.forge.name"`; each screen runs one localize pass.
- **The window:** search, filter by area (key prefix), "where used" with a jump to it, a
  missing/unused/untranslated report, and a **reviewed** tick per text to find the lines not yet
  rewritten.
- **Phased:** 1) table + window + lookup + tests (**done 2026-10-30**: `ImmoralityGaming/Localization/`,
  `Tools ▸ Texts`, `LocTests` 9/9); 2) content assets, tutorial, room events (**done 2026-10-30**:
  764 texts migrated, 346 assets reserialized, all 1668 EditMode tests pass); 3) UXML (**done
  2026-10-30**: 122 labels → 104 `ui.*` keys, shared ones under `ui.common`; the four document
  controllers call `Loc.Localize(root)` once; no raw `#key` on the title, hub, room or combat UI);
  4) C# strings (**done 2026-10-30**: 1,084 texts in ~55 files under `combat.`, `room.`,
  `event-text.`, `dungeon.`, `abilities.`, `hub.`, `items.`, `menu.`, `grid.`, `bestiary.`, `stat.`,
  `framework.`; the table holds 1,952; 0 missing / 0 unused; 1,669 tests pass; checked in play).
- **Left for the rewording pass / a later localization pass** (found while moving, wording kept as-is):
  - Enum names still shown raw: damage types ("Normal" not "Physical" on grid resist nodes), some
    statuses (Frozen, Slow, Haste in the bestiary), `BuffType` in affliction lines, `StatType` in the
    enemy Weaken log ("MaxHealth"). They are passed as placeholder values; a translation needs them
    keyed too.
  - English grammar in code: summon plurals (`SummonOps.Plural`), "a"/"an", enemy-name plurals in run
    history (`RunHistory.Plural`). Fine for English, a rework for other languages.
  - Grid nodes show the raw ability/summon/Ultra **key** in some payload lines (as before).
  - "They leads the party." (`hub.camp.feedback.they-lead`) — kept word for word.
  - `AbilityDescriber.StatusLine` edits buff text after lookup (`.Insert("%")`, `.Replace(" 0", "")`);
    fragile once the wording changes.
  4) C# strings, screen by screen. Each phase compiles and runs on its own.

## 2. Accepted, to do now

  and the plate showed living units only; a held plate (`HealthDisplay.IsHeld`) now stays until its
  hit lands. Not yet seen in play.

  verify, change nothing if so.

**Keyboard**

**Runs**

  cave wall, or the cave going deeper). Today they float over a background.
